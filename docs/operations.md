# Operating the integrated pilot

## Configuration and secrets

`deployment/integration.librechat.yaml` is generated by `tools/prepare-integration.cjs`.
The optional top-level `hermes` block defaults to disabled when absent; existing LibreChat
deployments therefore retain their current behavior unless they opt in.

| Setting | Meaning |
| --- | --- |
| `hermes.publicOrigin` | Exact browser origin; no path or trailing subpath |
| `hermes.dashboardURL` | Fixed internal dashboard origin, normally `http://hermes:9119` |
| `hermes.runtimeURL` | Fixed internal API origin, normally `http://hermes:8642` |
| `hermes.managedOnly` | Restrict interactive chat to the Hermes endpoint |
| `hermes.allowedUserIds` | Additional trusted management operators; administrators already qualify |
| `HERMES_BRIDGE_KEY` | Private LibreChat-to-adapter key, at least 32 characters |
| `HERMES_API_KEY` | Existing default Hermes API-server key |
| `HERMES_DASHBOARD_USERNAME/PASSWORD/PROVIDER` | Server-side Hermes dashboard login; compose maps the existing pilot credentials |
| `GATEWAY_MULTIPLEX_PROFILES` | Enables named-profile execution on the shared gateway listener |
| `HERMES_DASHBOARD_PUBLIC_URL` | Public LibreChat origin plus `/hermes-workspace`, used for OAuth callback generation |

Never commit the private `.env` file or run unrestricted `docker compose config` into public logs.
Use `docker compose ... config --quiet` for validation. Preparation preserves existing secrets;
do not replace the server's existing `.env` with a fresh local file when upgrading AWS.

## Existing AWS host

This change has not been applied to the running EC2 server. To upgrade it, build the modified
LibreChat image from `src/LibreChat`, preserve the existing private environment and named data
volumes, prepare configuration using the real HTTPS origin, and apply the integration override
after the deployment's current compose overrides. Make sure `build.context` points to the copied
source tree; it is relative to the first compose file's directory.

The base compose project is named `librechat-hermes-pilot`. Keep that project name to retain the
existing MongoDB, Hermes-home and file volumes. Existing feature services can remain in the
compose file set; the integrated configuration disables their native LibreChat tool runtime.
Keep a copy of the old compose files and `librechat.yaml` to roll back the image/configuration.
Do not use `down --volumes` for an upgrade or rollback.

The optional new Caddy template serves the LibreChat hostname only. Keep a previous HTTPS
override if its additional routes are still needed, or adopt `compose.https.yaml` intentionally.
Hermes port 8642 stays private and should not be exposed through the public security group.

## Common failures

| Signal | Action |
| --- | --- |
| No Hermes sidebar entry | Check LibreChat account role / `allowedUserIds` and feature configuration |
| `HERMES_ORIGIN_REFUSED` | Regenerate configuration with the browser's exact origin and restart LibreChat |
| `HERMES_UNAVAILABLE` | Check dashboard health, password-provider credentials and network reachability; use Retry |
| `HERMES_WORKSPACE_SESSION_EXPIRED` | Reopen/retry the workspace; a LibreChat login may need refreshing |
| `HERMES_PROFILE_OR_MODEL_NOT_READY` | Enable the profile, confirm its API server and multiplexing, reload the gateway if required, and retry |
| `HERMES_SESSION_CONTEXT_REQUIRED` | Keep the server-side user/conversation header templates in the custom endpoint |
| `HERMES_EXECUTION_REQUIRED` | Select Hermes; native agent IDs and direct-provider execution are disabled |
| `HERMES_CONFIGURE_TOOLS_IN_WORKSPACE` | Configure the tool in Hermes instead of adding a LibreChat-native tool |
| MCP OAuth returns to an internal host | Check `HERMES_DASHBOARD_PUBLIC_URL`, including the workspace prefix |
| Tool appears but cannot execute | Check Hermes's prerequisites, provider credentials, backend choice and `api_server` tool permissions |

Hermes resources apply to new sessions. Starting a new LibreChat chat creates a fresh session
namespace; refreshing an existing chat does not intentionally rebuild its Hermes prompt/tools.
Gateway reloads may interrupt active runs, so the integration reports that requirement rather
than force-restarting the gateway during ordinary model listing or profile creation.
